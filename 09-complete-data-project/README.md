# 第六章：完整数据项目实践

> 本章目标：把环境、Git、数据探索、清洗、特征、训练、评价和结果交付串成一个可复现的小型项目。学习者需要自己作出选择，不再照抄逐行答案。

## 1. 从练习题走向项目

前几章的任务通常告诉你要调用哪个函数。本章只给出任务说明、数据字典、最低要求和验收标准。你需要自己决定：先检查什么、怎样处理缺失、使用哪些特征、选择什么模型，以及如何证明改动有效。

项目不是“得到一个分数”就结束。合格成果还应做到：

- 新电脑上能根据说明重建环境。
- 从原始数据到最终结果可以重复运行。
- 原始数据不被覆盖。
- 每项处理规则与实验改动都有记录。
- 代码、输出和 README 结构清楚。

## 2. 推荐项目结构

```text
final-data-project/
├─ data/
│  ├─ train.csv
│  └─ predict.csv
├─ output/
│  ├─ figures/
│  ├─ experiment_results.csv
│  └─ predictions.csv
├─ src/
│  ├─ explore.py
│  ├─ train.py
│  └─ predict.py

```

不要把 Conda 环境、缓存、临时文件和敏感信息提交到 Git。原始数据是否能上传，要遵守数据提供者的许可；不确定时先放入 `.gitignore` 并询问老师。

## 3. 完整工作流

### 3.1 创建项目与环境

创建独立目录和 Conda 环境，安装所需库，导出 `environment.yml`。在 VS Code 中选择正确解释器。初始化 Git 仓库，并在开始编码前准备 `.gitignore`。

第一次提交可以只包含目录说明、环境文件和 README 框架，例如：

```text
Initialize data project structure
```

### 3.2 获取并理解数据

阅读任务说明与数据字典，确认：

- 一行代表什么对象。
- 目标列是什么，属于分类还是回归。
- `train.csv` 与 `predict.csv` 有什么差别。
- 每个字段的单位、取值范围和产生时间。
- 哪些字段在实际预测时不可获得。

把理解写进 README，不要只留在脑中。

### 3.3 数据探索

至少检查：数据形状、样例、类型、缺失、重复、目标分布、数值分布、类别频率、可疑异常和主要变量关系。只绘制能够回答问题的图。

探索代码放在 `src/explore.py`，图保存到 `output/figures`。不能依赖手工点击才能重新生成。

### 3.4 清洗与预处理

为每个问题制定规则并说明理由。训练集与待预测数据必须使用同一套字段和转换。会从数据中学习参数的步骤，如中位数填补、缩放和 one-hot 编码，应放入 Scikit-learn Pipeline，并只从训练部分学习。

### 3.5 特征构造

新特征应满足三个条件：

1. 从预测时确实可获得的信息计算。
2. 有清楚、合理的含义。
3. 能在训练数据和待预测数据上用同一代码生成。

先建立不加复杂特征的基础方案，再一次增加一个改动并记录结果。

### 3.6 划分、训练与评价

根据任务选择指标，固定随机种子，建立简单基线。保留一份验证数据或采用合适的交叉验证。比较训练与验证表现，检查是否存在明显过拟合。

至少比较三个方案：基线、基础模型、一次有理由的改进。不是所有改进都必须提高分数；如实记录无效实验同样重要。

### 3.7 对新数据预测

训练方案确定后，对 `predict.csv` 应用同一预处理和模型，生成 `output/predictions.csv`。输出至少包含唯一编号和预测值，并检查：

- 行数与 `predict.csv` 一致。
- 唯一编号顺序没有错乱。
- 列名符合任务要求。
- 没有额外索引列。
- 预测值类型和范围合理。

### 3.8 整理与提交

删除调试残留，但不要删除实验记录。README 至少包含项目目标、环境、数据说明、运行方法、探索发现、处理规则、实验结果、最终方案和限制。

提交前依次检查：

```powershell
git status
git diff
python src/explore.py
python src/train.py
python src/predict.py
```

确认没有秘密、私人路径和无关大文件，再 Commit。

## 4. 最终实验：二手设备价格预测

### 4.1 项目背景

某校园循环平台希望根据二手设备的基本信息估计合理价格，帮助工作人员快速发现明显不合理的挂牌价。老师将提供两份此前未在教程中使用的数据：

- `train.csv`：包含设备特征与已知成交价。
- `predict.csv`：只有设备特征，需要生成预测价格。

这是一项回归任务。模型输出仅作为练习结果，不直接替代真实交易判断。

### 4.2 数据字典

| 字段 | 含义 | 类型与提醒 |
| --- | --- | --- |
| `item_id` | 设备唯一编号 | 标识字段，不直接作为数值特征 |
| `category` | 设备类别 | 类别数据 |
| `brand` | 品牌 | 类别数据，可能有少量缺失 |
| `age_months` | 已使用月数 | 数值数据，检查负数和极端值 |
| `original_price` | 原始购买价 | 数值数据，单位为元 |
| `condition` | 成色等级 | 类别数据，阅读说明后决定是否有序 |
| `has_warranty` | 是否仍有保修 | 二元类别 |
| `repair_count` | 维修次数 | 非负整数 |
| `description_length` | 描述文本长度 | 非负数值 |
| `sale_price` | 实际成交价 | 训练标签，仅存在于 `train.csv` |

若实际文件与数据字典不一致，应记录差异并向老师确认，不要偷偷修改任务定义。

### 4.3 项目任务书

你需要独立完成以下成果，但不提供固定代码顺序：

1. 创建项目、独立环境和 Git 仓库。
2. 写出数据检查报告，指出至少 3 个值得处理或关注的问题。
3. 制作至少 3 幅有明确问题和结论的图。
4. 构建可同时处理数值列与类别列的预处理流程。
5. 正确划分特征与标签，不把 `sale_price` 或其变形放入特征。
6. 建立 DummyRegressor 均值基线。
7. 训练至少两个正常回归模型，其中至少一个是课程中未直接给出完整答案的模型。
8. 使用固定方案进行交叉验证，以 MAE 为主指标，同时记录 RMSE。
9. 完成至少一次简单特征构造，并用实验结果判断它是否有效。
10. 选择最终方案，对 `predict.csv` 生成预测文件。
11. 编写 README，提交清楚的 Git 历史。

## 5. 必须回答的分析问题

- 数据规模、字段类型和缺失情况如何？
- 成交价分布是否偏斜，是否有极端值？
- 不同设备类别的价格分布有什么差异？
- 使用月数与成交价之间是否存在可见关系？
- 哪些处理规则会影响训练结果？为什么这样选择？
- 模型比基线好多少？各折结果是否稳定？
- 增加的特征是否带来稳定改善？
- 最终模型有哪些限制，在哪些数据上可能不可靠？

## 6. 实验记录要求

`output/experiment_results.csv` 至少包含：

| 字段 | 内容 |
| --- | --- |
| `experiment_id` | 唯一实验编号 |
| `change` | 相比上一实验的唯一主要改动 |
| `model` | 模型名称 |
| `features` | 使用的特征版本 |
| `cv_mae_mean` | 交叉验证平均 MAE |
| `cv_mae_std` | MAE 波动 |
| `cv_rmse_mean` | 平均 RMSE |
| `random_state` | 随机种子 |
| `conclusion` | 保留、放弃或继续验证及理由 |

推荐实验次序：

| 实验 | 主要内容 |
| --- | --- |
| E00 | DummyRegressor 基线 |
| E01 | 基础预处理 + 基础模型 |
| E02 | 相同预处理 + 第二个模型 |
| E03 | 在较好方案上增加一个特征 |
| E04 | 只修改一个模型参数 |

如果某次结果变差，也应保留记录并解释，不要删除“失败实验”。

## 9. 阶段检查点

本项目分四次检查，避免最后一天才发现基础流程错误：

### 检查点 A：项目可运行

环境、目录、Git 和数据读取正确，README 已说明任务。

### 检查点 B：数据已理解

探索脚本可重复运行，图表有标题，质量问题与处理计划清楚。

### 检查点 C：实验可比较

基线和至少两个模型完成，预处理无明显泄漏，结果表能够公平比较。

### 检查点 D：交付可复现

从干净环境按 README 能生成实验结果和最终预测，Git 中没有敏感或无关文件。

## 10. 评分与验收

| 方面 | 比例 | 重点 |
| --- | ---: | --- |
| 项目结构与环境 | 10% | 目录清楚、环境可恢复 |
| 数据理解与探索 | 20% | 检查充分、图表回答问题 |
| 清洗与预处理 | 20% | 规则合理、一致、无明显泄漏 |
| 模型与评价 | 20% | 有基线、公平比较、指标正确 |
| 实验改进 | 15% | 一次改一项、有记录、有判断 |
| 结果与文档 | 15% | 预测格式正确、README 可复现 |

以下情况需要优先修正，即使模型分数较高：标签泄漏、训练与验证混用、无法重新运行、覆盖原始数据、预测文件编号错位、提交敏感信息。
